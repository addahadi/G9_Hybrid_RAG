# G9 — Hybrid RAG for Image Captioning (MS COCO)

A comparative study of Retrieval-Augmented Generation (RAG) techniques for image captioning.
**Group G9 · Technique: Hybrid RAG (dense CLIP retrieval + sparse BM25, fused with Reciprocal Rank Fusion).**

## Preprocessing results (Phase 1)

- **Splits** (seed 42): knowledge base 10,000 (train2017) · validation 100 · test 100 (val2017). No overlap.
- **Captions**: 50,000 (5 per image); raw kept for evaluation, cleaned copy used only for retrieval.
- **Embeddings**: CLIP ViT-B/32, 512-d, L2-normalised (10,000 image + 50,000 text vectors).
- **Indexes**: FAISS `IndexFlatIP` (images, captions) + BM25Okapi. Build times 0.014 s / 0.153 s / 1.011 s.
- **Audit**: 13/13 automated checks pass ([`results/preprocessing_release/preprocessing_audit.json`](results/preprocessing_release/preprocessing_audit.json)).
- **EDA**: all 80 COCO categories, 7.21 objects/image (median 4), captions 10.49 words avg, vocabulary 9,770.

Full write-up: [`docs/report/G9_Preprocessing_Report.pdf`](docs/report/G9_Preprocessing_Report.pdf).

## Reproducing Phase 1

1. Open the notebooks in `notebooks/preprocessing/` in Google Colab (T4 GPU for notebook 01), in order `00 → 01 → 02`.
2. They mount Google Drive and read/write `MyDrive/G9_Hybrid_RAG/` (set by `ROOT` in each notebook). The layout there mirrors `data/` and `results/` here.
3. Regenerate the figures locally: `pip install -r requirements.txt && python scripts/make_figures.py`.

> ⚠️ Never change split IDs or overwrite embeddings/indexes without regenerating every split-dependent artifact. Do not load `bm25.pkl` from untrusted sources (pickle).

## Anti-leakage rules (from the brief)

Test-image reference captions are never in the knowledge base, never used for retrieval/generation, and a test image is never retrieved for itself (KB = train2017, test = val2017, so this holds by construction).
